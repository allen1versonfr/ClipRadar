# 3.2.0: nothing gets lost (persistence, stable clip numbers, reliable exports)

Roadmap item 1 of the Clip Control plan. Planned in chat, executed in Claude Code.
Ship as **3.2.0** when every part below is done and CI is green.

## What's wrong today (verified in the code)

1. **Clip numbers aren't stable, and review work can jump to a different clip.**
   `engine.pick_clips` sets `c.id = i` (rank position 1..N) on every pick. The UI keys clips by
   `pid:id` (`keyOf` in `ui/app.js`). `repick()` reuses old state with
   `old.get(keyOf(s)) || prepClip(s)`, so after a Clips, Length or Chat-vs-audio slider change, a
   kept, trimmed or retitled clip #3 hands its state to whatever moment is now rank 3. Queue items
   store `clip_id`, so `queueFor(c)` can mark the wrong clip "Rendered".
2. **The render queue and Exports live only in memory** (`queue` list in `server.py`). After a
   restart, Exports is empty even though the mp4s are on disk, and queued or failed renders are gone.
3. **Review state lives only in the page** (`W.clips` in `app.js`): kept/skipped, trims, titles,
   post captions and caption edits. Reopening a recent VOD makes a new `pid` (uuid), re-analyzes and
   starts review from zero.
4. **A crashed or killed render leaves a broken mp4 under the real name.** `render_clip` writes
   straight to the final path. The next attempt then becomes "title (2).mp4", next to the broken one.
5. **A retry makes a new file name** instead of replacing its own failed or partial file.
6. `engine._save_meta` writes meta.json in place, so a crash can corrupt it.

## Design

### A. Stable clip identity (do this first; everything else keys off it)
- Each project keeps a counter and a list of known moments: `{num, start, end, peak}`.
- After any pick or repick, match each new clip to a known moment. It's the same moment if the
  peaks are within 8 s, or the clips overlap by at least 50% of the shorter one. Matched clips keep
  their `num`; unmatched ones get `counter += 1`. Numbers are never reused, even when a clip drops
  out of the list.
- Gems use the same counter and matching, keeping `kind: "gem"`. Drop the `GEM_ID` offset as an
  identity and use `kind` instead. `id` becomes the stable `num`; keep `rank` as the score order.
- Hand-added clips (`/api/add_clip`) get the next number.
- When a matched clip has user state (kept, skipped, user trim, edited title or words), the
  server keeps the user's start/end, not the re-picked bounds.
- UI: show `#num` on rows and in the inspector. `keyOf` stays `pid:id`, which is now safe.
- Unit test (`tests/test_persist.py`): repick with count 10 → 20 → 5 → 10 keeps every surviving
  moment's number, and new moments get new numbers.

### B. Project file (review state survives restarts)
- `pid` is derived from the workdir folder name (stable across runs), not `uuid4`.
- `workdir/project.json`, written atomically (`.tmp` + `os.replace`), with a `"v": 1` schema
  number. It holds: source, title, streamer, slider settings (count, length, chat weight,
  chat delay), the counter and known moments, and per clip: `num, kind, start, end, rank, state
  (todo|kept|skipped), user_trim, title, title_edited, post, words (if edited), held`.
- New endpoint `POST /api/clip_state {pid, id, ...fields}`: the UI calls it on keep, skip, undo,
  trim, title or post edit, and caption edit. The server merges the fields and saves (debounce
  about 1 s, and always flush on shutdown).
- Reopening a source that has a project.json (and whose video signature matches, like
  `_video_sig`): restore the clips and states instead of re-picking. Still run `analyze` for the
  curve, scores and repick, but cache the Analysis arrays in `workdir/analysis.npz`. Key the cache
  on the video signature, the chat file size and an `ANALYSIS_VERSION` constant in engine.py, so a
  reopen is instant and a detector change invalidates it.
- If the signature doesn't match (the VOD was re-downloaded differently), keep project.json as
  `project.old.json` and start fresh.
- Recent list (`engine.recent_projects`): show "N kept · M to review" when project.json exists.

### C. Persistent render queue and Exports
- `DATA_DIR/queue.json` (atomic). Write it on add, remove, status change and done; throttle
  progress-only writes to 1 per 5 s, or skip them.
- Each item stores what a render needs without the project in memory: `video, workdir, title,
  has_audio, opts, words, start, end, pid, clip_id(num), name, status, error, attempts, tiktok`.
  `_render_item` loads the project lazily from project.json when `projects[pid]` is missing.
- On startup: `done` items whose file still exists are listed, and missing files are dropped.
  `rendering` items become `queued` and resume, and so do `queued` items. `error` items stay, with
  Retry.
- Exports keeps its current UI and simply survives a restart. `queueFor(c)` matches on the stable
  `clip_id`.

### D. Export reliability
- Choose the file name **once**, when the item first renders, and store it on the item. A retry
  reuses that name and overwrites its own file. "(2)" only applies against files that belong to
  *other* items.
- Render to `<name>.part.mp4` in the same folder, then `os.replace` to the final name only after
  validation. Write the post `.txt` atomically too.
- Validate with ffprobe before marking done: there's a video stream, the duration is within
  0.5 s of `end - start`, and the size is over 0. If that fails, the error is "The rendered file
  came out broken" and it retries once automatically.
- Automatic fallback: if the error is the encoder one (`nvenc|qsv|amf|error while opening
  encoder`), retry once with `hw_encode=False` before reporting failure, and log it.
- Pre-flight disk check: estimate the size (`duration * 1.5 MB/s` is a fine upper bound at
  1080x1920) plus 200 MB, compare it with `shutil.disk_usage(outdir).free`, and raise the
  existing "drive is full" message before starting.
- Startup cleanup: delete `*.part.mp4` in the `tiktok/` folders under WORKROOT.
- Make `_save_meta` atomic.

## Tests (add to existing suites; CI must stay green)
- `tests/test_persist.py`: moment matching and numbering; project.json round trip; queue.json
  restore (rendering→queued, done-but-missing dropped); name reuse on retry.
- `tests/e2e.py`:
  - change the Clips slider after keeping clip N, and check the kept clip keeps its number,
    bounds, title and Rendered badge;
  - restart the app (kill and relaunch) with one done and one queued item; after the restart,
    Exports lists the done file and the queued one finishes;
  - reopen the same VOD; check the kept and skipped states and the edited title are back;
  - use a `TEST_HOOKS` "die mid render" path: no final-name mp4 is left behind, and Retry
    produces the same name with no "(2)";
  - use `fail_next_render` with the encoder error message: it succeeds on the CPU fallback.
